# Generated: holoscan.schema.Image FlatBuffers TypeScript bindings

Everything under `holoscan/` in this directory is generated by `flatc`, checked in rather than
built on the fly (this package's own build is plain `tsc`/`esbuild` via `foxglove-extension`, with
no `flatc` step of its own). Do not hand-edit.

Used only by `../../converters.ts`'s `decodeHoloscanSchemaImageMetadata()`, to decode the nested,
independently-encoded `holoscan.schema.Image` bytes carried inside a
`isaac.mcap_logger.TensorFrame.metadata` field -- see that function's comment for why this
second decode step is necessary at all.

## Regenerating

Source schemas live in the Holoscan SDK, not this repo:

```bash
HOLOSCAN_SDK=/path/to/holoscan-sdk   # e.g. wherever the CPM cache checked it out
STAGE=$(mktemp -d)
cp "$HOLOSCAN_SDK/public/src/sensor_io/schemas/image.fbs" "$STAGE/"
cp "$HOLOSCAN_SDK/public/schemas/header.fbs" "$STAGE/"
cp "$HOLOSCAN_SDK/public/schemas/time.fbs" "$STAGE/"
cp "$HOLOSCAN_SDK/public/schemas/tensor.fbs" "$STAGE/"

OUT=src/generated/holoscan-schema
flatc --ts -o "$OUT" "$STAGE/image.fbs"
flatc --ts -o "$OUT" "$STAGE/header.fbs"
flatc --ts -o "$OUT" "$STAGE/time.fbs"
flatc --ts -o "$OUT" "$STAGE/tensor.fbs"

# flatc's TS codegen always suffixes relative import specifiers with .js (an ESM-oriented
# default), but this package's tsconfig ("module": "commonjs", "moduleResolution": "node") and
# webpack build (foxglove-extension build) both resolve extensionless specifiers -- a .js suffix
# on a specifier pointing at a real .ts file fails to resolve at build time (tsc --noEmit alone
# won't catch this; only the actual webpack build does). Strip it:
grep -rl "from '\.\./\|from '\./" "$OUT" | xargs sed -i "s/\.js';/';/g"
```

The staging step matters: `image.fbs`'s `include "header.fbs"` (etc.) must resolve against copies
sitting next to it, matching how the Holoscan SDK's own C++ codegen stages these same schemas
(`sensor_io/schemas/CMakeLists.txt`'s `SENSOR_IO_SCHEMA_STAGE_DIR` -- see that file's comment: flatc
records each include's path into the compiled binary schema, so compiling against a differently
laid out `-I` path would change `Image`'s recorded schema identity).

Re-run this whenever `holoscan.schema.Image` (or `Header`/`Time`/`Tensor`) changes shape.
